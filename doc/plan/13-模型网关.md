# 13 模型网关

> 目标是让用户选“标准”或“深度”就能开始任务。网关把这个选择映射到实际模型，内置助手继续负责对话、调用工具和取消任务。
>
> 相关 [01 架构](01-架构.md) · [03 内置运行时](03-内置运行时-Dim.md) · [08 通用任务化](08-通用任务化改造.md) · [10 里程碑](10-里程碑与验收.md)

## 1. 先验证一个模型

- **M0【建议】** 先用测试上游跑通 `standard`，再换成一个真实的 Chat Completions 模型。验收桌面流式输出、一次工具调用与取消。模型来源和具体厂商留待 Q-03 确定。
- **首发【建议】** 公开版以产品提供模型为目标。用户完成产品自己的登录或授权后就能发消息。开发和内测可以先走自带 API Key，界面清楚说明首次配置要求。
- **深度【待验证】** 保留 `deep` 作为第二个产品别名。它依赖通过 ACP 选择模型的能力，以及上游在深度配置下仍能正确调用工具。通过验收后再显示入口。

| 别名 | 界面标签 | 网关映射 | 产品行为 |
|---|---|---|---|
| `standard` | 标准 | 一个已验收的模型和默认生成配置 | 新对话默认使用 |
| `deep` | 深度 | 已验收的深度模型，或同一模型的较高推理配置 | 由用户选择，界面说明响应可能更慢 |

别名是产品稳定 ID。界面通过翻译表显示标签，T3 按自身的会话状态保存选择。网关按别名路由。替换模型时，先比较上下文长度、输出上限和工具能力，再发布路由。一次模型 HTTP 请求使用一个路由快照，进行中的流式回复继续使用发起时的配置。

## 2. 接口和进程边界

```text
聊天框 → T3 服务端 ──ACP──▶ 内置助手 ──HTTP + SSE──▶ 模型网关 → 模型厂商
                    ▲             │
                    └──── MCP ────┘
                          │
                     已授权的插件
```

聊天、会话恢复和工具结果仍由 T3 与运行时处理。网关只处理模型 HTTP 请求。插件产生的内容通过上下文或工具结果进入该请求。产品要在初次启用云端模型、首次引用笔记的流程中说明，这些发给助手处理的内容可能随对话发送到配置的模型服务。自带 Key 的网关运行在本机，模型推理地点取决于设置里的服务地址。

| 方式 | 模型网关 | 凭据 | 用户体验 |
|---|---|---|---|
| A 产品提供模型【建议首发】 | HTTPS 云端服务 | 桌面端持有可撤销的产品令牌。云端单独配置模型厂商的密钥 | 登录或授权后可以开始对话。网关按账号限制并发与用量 |
| B 自带 API Key【建议先用于内测】 | 本机 Go 服务，由 T3 服务端监管，监听 `127.0.0.1` | 本机网关从系统钥匙串取厂商密钥。助手只接收本次启动的网关令牌 | 初次在“设置 → 模型服务”填地址和密钥，连接验证后发送 |

B 的 Go 服务是独立实现，可随桌面 app 一起启动，也可和 T3 服务端一起运行。用户操作入口由 T3 提供。网关采用私有进程通道接收配置更新，回传就绪地址和连接状态。窗口创建和进程监管仍按 [04 mygo 外壳](04-mygo外壳.md) 的启动契约执行。

## 3. Dim 与 T3 已核实的约束

- Dim `v0.1.0-alpha.25` 的 `--model-config` 支持 `defaultModel`、`providers[].{id,kind,apiKeyEnv,baseUrl,models}`。每个模型的 `contextWindow`、`maxOutputTokens`、`config.maxTokens` 都需要填。配置项以发布 tag 为准。文件里的 `kind` 使用 `openai-chat`，Bedrock 被该配置加载路径拒绝。 [Dim 配置类型](https://github.com/arcships/dim/blob/v0.1.0-alpha.25/crates/dim-agent-aimux/src/config.rs#L34-L63) · [模型配置校验](https://github.com/arcships/dim/blob/v0.1.0-alpha.25/crates/dim-agent-aimux/src/models.rs#L33-L105)
- `apiKeyEnv` 是取密钥的环境变量名。对于 Chat Completions，请求用 Bearer 头。将该值设置为**网关令牌**，厂商密钥留在网关一侧。 [Dim 请求凭据解析](https://github.com/arcships/dim/blob/v0.1.0-alpha.25/crates/dim-agent-aimux/src/plugin.rs)
- **模型切换是个单独的验证项。** alpha.25 的 ACP 模型选项依赖产品目录 `provider.catalog` 和 `session.model.update`，`--model-config` 走开发目录。单纯在 JSON 增加 `deep` 不会在 T3 里得到可用的切换按钮。T3 的 ACP 适配支持读取 agent 报告的 `configOptions` 及模型列表。M0 先抓 `session/new` 结果，M1 在单别名配置下隐藏选择器。后续优先用上游支持的 ACP 选择能力，验收后开放到对话。 [Dim ACP 模型选项](https://github.com/arcships/dim/blob/v0.1.0-alpha.25/crates/dim-acp/src/config.rs#L124-L207) · [T3 ACP 探测](https://github.com/pingdotgg/t3code/blob/3ce2145864f1e8b822cc8dff9c8cfdf39d9e450b/packages/provider-acp-registry/src/server/probe.ts#L214-L263) · [ACP 会话选项](https://agentclientprotocol.com/protocol/v1/session-config-options)
- **令牌绑定运行时进程。** T3 的 Local command 会传递解析出的 provider 环境。Dim 再启动私有 daemon。alpha.25 用模型配置文件哈希识别 daemon 配置，单独换环境变量不能保证 daemon 重载。M0 验证令牌注入、首次启动和退出。更换网关地址、本机令牌或云端登录态时，由服务端收尾或取消在跑的回合，再重启这个产品私有的 daemon。云端方案在发布前还要验证凭据更新和恢复旧对话。 [T3 Local command](https://github.com/pingdotgg/t3code/blob/3ce2145864f1e8b822cc8dff9c8cfdf39d9e450b/packages/provider-acp-registry/src/server/AcpRegistrySupport.ts#L1854-L1876) · [Dim daemon 启动](https://github.com/arcships/dim/blob/v0.1.0-alpha.25/crates/dim-cli/src/client.rs)

M0 生成的 `runtime/model.json` 示例。端口和 token 上限用测试值，正式配置以锁定模型的能力为准。

```json
{
  "defaultModel": { "providerId": "gateway", "modelId": "standard" },
  "providers": [
    {
      "id": "gateway",
      "kind": "openai-chat",
      "apiKeyEnv": "XTWORK_MODEL_GATEWAY_TOKEN",
      "baseUrl": "http://127.0.0.1:18080/v1",
      "models": [
        {
          "id": "standard",
          "contextWindow": 32768,
          "maxOutputTokens": 8192,
          "config": { "maxTokens": 4096 }
        }
      ]
    }
  ]
}
```

云端模式把 `baseUrl` 换成产品网关的 HTTPS 地址，同一份模板继续使用。路由对应的实际模型、生成参数和凭据由网关配置持有。实际模型与网关必须支持模板声明的上下文和输出上限。缩小上限前先验收旧对话的上下文整理。

## 4. 转发与流式输出

| 环节 | 首版约定 |
|---|---|
| 接收 | `POST /v1/chat/completions`，校验 Bearer 令牌、JSON 请求大小、请求中的 `model`。模型地址来自网关已保存配置。 |
| 转发 | 查别名，替换 `model`，按该路由配置写入必要的生成参数和厂商凭据。保留消息、`tools`、`tool_choice` 和流式选项。 |
| 流式成功 | 透传 SSE，并及时 flush。保留文本增量、工具调用参数分片、`finish_reason`、可用的 `usage` 和结束标记。 |
| 流开前失败 | 返回 Chat Completions 兼容错误结构。区分未配置、凭据失效、限流、上游不可用及无效请求。限流时保留有效的 `Retry-After`。用户主界面只显示可操作的故障原因。 |
| 流开后失败 | 让运行时看到流中断并结束当前回合。收到半个工具调用时等待完整参数或以失败结束。用户可从对话里重试，根据工具执行记录确认之前已发生的写入。 |
| 用户取消 | 由 T3 发起 ACP 取消，网关随下游断开取消上游请求，释放连接及并发名额。 |

首版用一个兼容 Chat Completions 的真实上游完成链路。Responses 和 Anthropic Messages 可按实际选定的模型独立接入。接入前用真实工具回合验证 token 参数、推理字段、增量工具调用和用量字段，避免跨协议转译提前占据 M0。 [OpenAI Chat Completions 接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

## 5. 凭据和设置

- **B 的设置**显示服务地址、连接状态和更新或移除密钥的入口。用户保存配置时先验证新密钥与模型，验证成功后切换生效。网关用操作系统钥匙串保存密钥，并在私人控制通道上返回状态和原因。上游 T3 的 `ServerSecretStore` 使用本机文件，v2 的模型密钥另外接系统钥匙串。 [T3 服务端凭据底层](https://github.com/pingdotgg/t3code/blob/3ce2145864f1e8b822cc8dff9c8cfdf39d9e450b/apps/server/src/auth/ServerSecretStore.ts#L139-L172)
- **A 的设置**显示产品账号连接状态与用量提示。云端网关在服务侧处理厂商密钥、用户额度和令牌撤销。退出账号后停止用该账号发新请求。
- **运行时**只收到用于模型请求的网关令牌，按需注入内置 ACP provider 的启动环境。配置文件、启动参数、WebView 注入和插件接口均不携带密钥。alpha.25 对执行的命令使用环境变量白名单，M0 和每次升级都验证令牌没有进入命令或插件 worker 的环境。 [Dim 命令环境白名单](https://github.com/arcships/dim/blob/v0.1.0-alpha.25/crates/dim-agent-capabilities/src/host_platform.rs#L188-L207)
- **诊断**记录时间、请求 ID、别名、状态、耗时与可用的用量摘要。原始模型请求、回复、笔记、工具参数与凭据不进网关日志。保留运行时 `model-log` 默认关闭的配置。云端留存与用户告知的具体口径在确定 Q-03 后一并确认。 [Dim 模型请求录制设置](https://github.com/arcships/dim/blob/v0.1.0-alpha.25/crates/dim-app-server/src/model_log.rs#L15-L30)

## 6. 验收

| 阶段 | 验收场景 | 通过条件 |
|---|---|---|
| M0 | 伪上游逐段流式响应，随后换真实上游 | 看到 `standard` 对应的真实模型请求。桌面逐段显示文本，完成一次测试 MCP 工具调用且工具结果进入下一请求。 |
| M0 | 取消、半帧断流、401、429、5xx | 取消关闭网络请求。断流结束当前回合且半截工具参数不执行。错误给出对应状态，令牌与正文未写到日志。 |
| M0 | 本机网关端口变更和应用重启 | 运行时获得新地址和令牌，旧令牌被拒，保存的会话可恢复。确认 shell 和 worker 环境均无该令牌。 |
| M1 | 自带密钥启用、更换、移除 | 用户可以在设置完成配置并发起新对话。验证失败时可继续使用原有配置，移除后后续请求提示重新配置。 |
| 云端开放前 | 首次授权、额度用尽、授权更新、退出 | 首次不填厂商密钥即可发送，额度提示可见，重新授权后可继续旧对话，撤销后旧令牌失效。 |
| 深度开放前 | 同一对话切换别名，重启后重新打开 | ACP 确认选择，网关收到正确的别名，工具调用保持可用。界面显示实际生效的选择。 |

核实基线为 2026-11-19 查阅的 Dim `v0.1.0-alpha.25` 和 T3 `3ce2145` 源码。上表是待执行的验收，模型网关仍处于规划阶段。
