# 03 内置运行时 · Pi

【已定】小瞳 Work 随应用交付 Pi 作为默认助手。Dim Agent Alpha 的生态与维护成本超出项目能承担的范围。决策从 [ADR-009](../decisions/009-default-pi-runtime.md) 生效，旧调研见 [Dim 归档](03-内置运行时-Dim.md)。

## 1. 用户怎样使用

打开小瞳 Work，新对话默认使用内置助手「**小瞳**」（实例 `xtworkPi`，按 [ADR-012](../decisions/012-xiaotong-model-channels-and-coding-agents.md) 由原「内置助手」更名，已于 [PR #24](https://github.com/oulkurt/Xtwork-v2/pull/24) 落地默认更名与 M1b-Gate 1 底座）。用户可通过企业微信扫码登录公司团队渠道（默认 `deepseek-flash`，M1b-Gate 2 在途）或在「小瞳」模型渠道中配置 19 类个人 API / OAuth 订阅供应商开始任务；同时可在设置中保留并一键安装 Claude Code / Codex / Kimi Code / Qoder / Codebuddy Code / DeepSeek Harness（M1c 在途），并在「Coding Agent」设置中选择「自动」（由小瞳直接执行）或指定外部编码 Agent（由小瞳经 T3 `delegate_task` 委派编码子任务）。开发预览仍保留本地 Magpie / 环境变量测试线路。 [早期规划原型（2026-11-19）](../../.smyw/20261119-xtwork-v2/preview.html) · [模型网关](13-模型网关.md) · [ADR-012](../decisions/012-xiaotong-model-channels-and-coding-agents.md)

```text
mygo → 随包 Node / T3 → 原生 provider-pi → 随包 Pi CLI（stdio RPC，“小瞳”）
                                              ├─ HTTP SSE（4 种原生协议）→ 本机保协议凭据隔离网关 → 公司渠道 / 19 类供应商
                                              ├─ 会话 MCP → T3 → Go 插件宿主 → worker（待办/日程/笔记）
                                              └─ 会话 MCP（delegate_task）→ T3 编排 → 选定的 Coding Agent（Claude/Codex/ACP）
```

## 2. 接口和所有权

| 调用方 | 调用 | 所管状态 |
|---|---|---|
| mygo → T3 | 用 `XTWORK_PI_BINARY` 提供随包启动器路径 | 外壳监管服务端，T3 监管 Pi RPC、网关和插件宿主 |
| T3 设置 → Xtwork 启动配置 | `startBundledPi(binaryPath, dataDir, env)` 返回注册表所需的 Pi 配置、私有启动环境和 `close()` | 只有产品实例 `xtworkPi` 得到私有环境。持久设置只保存实例元数据和模型选择 |
| T3 历史设置 → 当前设置 | `seedBundledPi(settings, firstRun)` 初始化或迁移产品默认项 | T3 保管 SQLite、线程和设置。Pi 把原生续聊会话存入应用数据目录 `runtime/pi/sessions` |
| Pi → T3 插件工具 | 上游适配层注入 T3 MCP 扩展，连接会话级 `/mcp` | T3 发放 MCP 令牌并归属调用。Go 宿主保存待办，面板和助手使用同一份数据 |

T3 原生 Pi 适配器已具备模型发现、取消、恢复、权限确认和 MCP 桥。Xtwork 管随包路径、私有目录、品牌提示、保协议模型网关（`runtime/gateway.ts` + `runtime/oauthProxy.ts` + `runtime/secretStore.ts`）与活跃会话热刷新（`overlay/patches/042-m1b-live-refresh.patch`）。预览使用 Pi `1.5.2`，由 npm lockfile 锁定依赖和 integrity，从本地制品中的 Node 启动。 [锁定 T3 的 Pi 帮助](https://github.com/pingdotgg/t3code/blob/3ce2145864f1e8b822cc8dff9c8cfdf39d9e450b/docs/user/providers-pi.md) · [T3 Pi 适配器源码](https://github.com/pingdotgg/t3code/blob/3ce2145864f1e8b822cc8dff9c8cfdf39d9e450b/packages/provider-pi/src/server/adapter.ts) · [Pi 依赖锁](../../runtime/pi/package-lock.json)

产品实例使用自己的 `PI_CODING_AGENT_DIR` 和会话位置。桌面服务的默认工作目录位于应用数据内的 `workspace`。启动参数关闭项目级自动加载和 Pi 启动时的联网检查，T3 仍显式加载 MCP 扩展。Pi 启动器过滤宿主环境，私有 `models.json` 只存网关令牌的环境变量名。shell 启动器在交给 Bash 前清掉产品模型网关和 T3 MCP 令牌。所有这些入口都适用当前预览的操作系统权限，审批属于 T3 与插件能力边界。 [Pi CLI](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/cli.md) · [Pi 的 shell 环境](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/src/utils/shell.ts)

## 3. 原有 Alpha 数据

- 新安装初始化 `xtworkPi`。升级时停用 `xtworkDim` 并清除旧启动路径。全局和项目里显式选了 Dim 的模型项迁到 Pi，覆盖默认、回退、后台生成、源码管理文案、审查指南和语音转写清理各自支持的设置。项目启用覆盖随实例迁移，空值和用户选择的其他模型继续生效。
- 既有线程记录、待办和 Dim 原生文件保留在原处，Pi 使用自己的原生会话 ID。查看旧对话后可以在 Pi 开新对话接续任务。旧线程的跨运行时续聊需要额外验收。
- 产品制品移除 Dim 安装器、运行时二进制和 ACP 产品配置。历史安装包仍对应其自己的已验收代码。[旧 Alpha 实现](../decisions/002-default-dim-runtime.md)

## 4. 接入取舍

采用原生 Pi CLI 和 T3 适配层，应用只补配置和打包。这条边界让 T3 和 Pi 分别维护 RPC、会话、模型与工具适配。Pi SDK 自建引导可以把凭据直接放到内存里，也会让 Xtwork 接管 CLI 参数、资源加载和恢复一致性。Pi 经 ACP 接入还要重新验收协议转换和工具能力。 [架构决策](../decisions/009-default-pi-runtime.md)

## 5. 验收与下一步

1. 在独立数据目录运行随包 Pi。用锁定版本验证模型发现、真实流式回复、待办工具创建与重启后原线程读回。
2. 用旧 Alpha 数据副本启动。核对默认切换、其他模型偏好、历史可见性、待办和插件行为，以及正常退出后 Pi 与 T3 子进程回收。
3. 在干净 Mac 验证无需全局 Pi、Node、额外登录。测试取消流、Supervised 批准与拒绝、模型和 MCP 令牌保护、私有会话路径和签名更新。正式首启凭据、第二模型和其他平台各自验收。

实跑命令与结果见 [桌面预览](../desktop-foundation.md)。完整发布要求见 [里程碑](10-里程碑与验收.md)。
