# 12 从 xtwork 迁移

【已定】v2 取代 xtwork。按你最新的决定，旧 `xtwork_mygo` 实现可跳过。v2 可以从干净目录和最新 mygo 起步，先交付新用户路径。

## v2 的起点

| 领域 | v2 的做法 |
|---|---|
| 桌面外壳 | 直接按当前 mygo 稳定版实现 [04](04-mygo外壳.md) 的最小外壳 |
| 会话和状态 | 交给 T3 的编排与持久化 |
| 助手 | 用开源 Dim 经本地 ACP 接入，由应用管版本与进程 |
| 插件 | 在 T3 服务端一侧建设 moejs 宿主和桥接 |
| 凭据 | 使用 v2 的钥匙串命名空间，首次连接时按产品路径配置 |
| 发布 | 使用 v2 的应用标识和更新源，沿用旧基础设施属于可选决定 |

## 可选参考

旧项目的待办、日程和笔记工具清单能帮助理解功能。原有夹具可以作为参考输入，v2 的测试以新契约、权限和用户行为为准。实现时只在确认某段代码能独立使用、许可清晰并且比重写更省工作时做局部移植。原生视图、旧 mygo 补丁、旧 agent sidecar 和整套宿主工程无需作为依赖引入。见 [05](05-插件系统.md) 中标为历史的协议与能力。

## 用户数据

- v2 使用独立目录。旧版数据保留在原位，用户可以并装回看。
- Obsidian 的笔记是 vault 内的文件。用户重新选择同一 vault 即可读到现有笔记，并按 v2 流程授权。无需导入 Markdown。
- 需要带走待办和日程时，再确认要支持哪些旧版本和导出格式。建议先预览记录数和冲突，保留原 id、日期、时区、完成状态及提醒，再由用户开始导入。
- 如果增加导入，导入过程使用源数据副本，重复导入按稳定来源 id 去重。先检查导入结果，再启用导入记录的提醒。
- 旧对话历史、插件授权、登录凭据的承接由 Q-05 明确范围。规划首轮验收使用干净数据目录。

## 切换验收

执行一次干净安装、一次与旧版并装启动。新应用只打开自己的数据库和凭据，旧应用仍可访问原记录。若提供导入，再覆盖一批重复导入、日期跨时区和 vault 重新授权的实测。
