# 01 架构

> 回答：产品由哪些进程组成，各自负责什么，数据怎样流动，依赖朝哪个方向。
> 相关：[02 上游与改造层](02-上游与改造层.md) · [03 内置运行时](03-内置运行时-Dim.md) · [04 mygo 外壳](04-mygo外壳.md) · [05 插件系统](05-插件系统.md)

## 1. 分层

| 层 | 技术 | 来源 | 职责 |
|---|---|---|---|
| 外壳 | mygo（Go） | 新写 | 窗口、系统集成、启动并监管服务端、桌面桥接 |
| 界面 | React | 上游 apps/web + 改造层 | 对话、设置、插件槽位 |
| 服务端 | Node（Effect） | 上游 apps/server + 改造层 | 编排、持久化、内置 MCP 服务、定时任务、插件桥 |
| 运行时 | Dim（Rust） | 官方二进制，锁定版本 | 执行对话：推理、调用工具、读写工作目录 |
| 插件宿主 | Go | 来自 xtwork | 插件注册、安装、授权、存储、监管 worker；运行 IM 连接器 |
| 插件 | moejs（TS/JS 沙箱） | 新写（部分来自 xtwork） | 待办、日程、笔记、远程连接的业务逻辑 |

## 2. 进程树

```
外壳（mygo，Go）
├─ 窗口：系统 WebView 加载 http://127.0.0.1:<端口>/（T3 界面）
│   ├─ PreloadScript 注入 window.desktopBridge → 调用外壳的 Go 服务
│   └─ 插件界面：沙箱 iframe（不透明源）
├─ 托盘、菜单、通知、更新
└─ 服务端（T3，Node）                        外壳启动并监管
    ├─ 编排 orchestration-v2、持久化、定时任务
    ├─ 内置 MCP 服务 /mcp                    运行时经它调用工具（按会话令牌鉴权）
    ├─ 插件桥（新增，TS）
    ├─ 运行时：<品牌>-agent acp …            即 Dim，ACP over stdio
    │   └─ Dim App Server 守护进程            Unix socket / Windows 命名管道
    └─ 插件宿主（Go）                         插件桥启动并监管
        ├─ IM 连接器：飞书 / 钉钉 / 企业微信长连接，微信长轮询待验证（可信 Go 代码）
        ├─ todo worker（moejs 进程）
        ├─ calendar worker（moejs 进程）
        ├─ obsidian worker（moejs 进程）
        └─ im-<平台> worker（moejs 进程）
```

产品提供模型服务时，网关在云端。自带密钥时，网关是由服务端监管的本机 Go 服务。见 [13 模型网关](13-模型网关.md)。

## 3. 依赖方向

```
插件（moejs） ──插件协议──▶ 插件宿主 ──插件协议──▶ 插件桥 ──内部服务──▶ T3 服务端
                                                            ▲
运行时（Dim） ──ACP──▶ T3 服务端 ◀──MCP──┘（运行时调用插件工具也走 MCP）
界面 ──T3 RPC / WebSocket──▶ T3 服务端
界面 ──postMessage──▶ 插件 iframe（只经宿主页面中转）
外壳 ──启动契约（--bootstrap-fd 0）──▶ T3 服务端
界面 ──DesktopBridge──▶ 外壳
```

规则：
1. 插件只认识插件协议。它看不到 T3 的 contracts，也看不到 Dim。上游怎么变，插件都不用改。
2. 插件宿主只认识插件协议和插件桥提供的“宿主能力”。
3. 只有插件桥依赖 T3 内部服务。上游变动造成的适配工作集中在插件桥这一处。
4. 外壳只依赖两样东西：服务端的启动契约和 `DesktopBridge` 接口。
5. 运行时只通过 ACP 和 MCP 与服务端交互。换运行时（例如临时换成 Pi）不影响插件。

## 4. 为什么插件宿主挂在服务端下，而不是外壳下

- 服务端是 agent 世界的中心：对话、工具（MCP）、事件、持久化都在这里。插件要做的事几乎都要经过它。
- 服务端可以脱离外壳运行。插件跟着服务端走，以后服务端跑在远程机器上，插件和远程连接照样工作。
- 外壳保持薄：只管窗口和系统。外壳的问题不会拖垮插件，插件的问题也不会拖垮窗口。

## 5. 关键数据流

### 5.1 聊天中提到待办

1. 用户在输入框写：“周五前把季度报告发给王总。”
2. 服务端把消息交给运行时。
3. 运行时根据系统提示中的插件规则，调用 MCP 工具 `todo__create({title: "把季度报告发给王总", due: "2026-11-20"})`（以 2026-11-19 发出消息为例）。
4. 服务端 MCP 服务把调用交给插件桥 → 插件宿主 → todo worker。worker 写入存储，返回新条目。
5. 插件桥发出事件，界面在对话里显示确认条：“已加入待办：把季度报告发给王总 · 周五”［撤销］［打开］。
6. 运行时继续回复用户。

### 5.2 引用 Obsidian 笔记

1. 用户在输入框输入 @，从笔记选择器里选一篇笔记；或者界面根据输入内容建议几篇相关笔记，以可移除的标签显示。
2. 界面给消息附上一个上下文条目：`kind: "obsidian-note"`，`payload: {path, title, content, truncated}`。
3. 服务端把未知类型的条目原样转成 JSON，放进发给运行时的 `<t3_context version="1">` 信封（`packages/shared/src/composerContextReferences.ts:394` 的 `projectComposerContextForProvider`）。**服务端不用改。**
4. 运行时读到笔记内容。需要更多内容时，再调用 `obsidian__read` 工具。

### 5.3 从飞书发起任务【建议，范围待确认】

1. 用户在飞书里给机器人发消息。
2. 插件宿主里的飞书连接器通过长连接收到事件，校验来源是已绑定的主人。
3. im-feishu worker 把消息映射成“在某个对话里发送一条消息”，调用宿主能力 `agent.thread.send`（或新建对话）。
4. 插件桥调用服务端内部服务执行。运行时开始工作。
5. 试点启用远程审批后，运行时请求权限时，插件桥把待处理请求交给 worker，worker 发一张带［批准］［拒绝］按钮的卡片。
6. 用户点按钮 → 连接器收到回调 → worker 调用 `agent.request.answer` → 运行时继续。
7. 回合结束，worker 把结果整理成卡片回复到飞书。

文本闭环和远程审批分别验收。平台连接方式见 [07](07-远程连接插件.md)。

## 6. 数据目录【建议】

```
<数据目录>/                 名称随品牌定【待定 Q-01】；不使用 ~/.t3
├── userdata/              T3 服务端状态（数据库、附件）
├── scratch/               免项目对话的工作目录
├── runtime/
│   ├── dim/               Dim 的 --home（不碰 ~/.dimcode-alpha）
│   └── model.json         Dim 的模型配置（不含密钥）
├── plugins/
│   ├── registry.json      插件宿主的注册表与授权记录
│   └── state/<插件 id>/   每个插件独立的状态目录
└── logs/                  外壳、服务端、插件宿主的日志
```

模型 API Key、IM 应用凭据由 v2 的系统钥匙串适配层保存。T3 原有服务端凭据存储独立，见 [13](13-模型网关.md)。

## 7. 生命周期

启动：
1. 外壳取得单实例锁，选端口。
2. 外壳启动服务端，经启动 stdin 传入配置；等待健康检查通过。
3. 外壳建窗口，加载界面。
4. 服务端启动插件桥；插件桥启动插件宿主；插件宿主按需启动插件 worker。
5. 用户发第一条消息时，服务端启动运行时会话；运行时连接或启动 Dim 守护进程。

退出：
1. 用户从托盘选“退出”，或系统关机。
2. 外壳在 `App.OnBeforeQuit` 中请求服务端优雅关闭。
3. 服务端关闭运行时会话、关闭插件宿主（插件宿主先停 worker，再断开 IM 长连接）。
4. 超时后，外壳只结束自己记录过 PID 的进程。
5. 验收：退出后没有残留进程（服务端、Dim 守护进程、插件宿主、worker）。

## 8. 与 xtwork 架构的差异

| 方面 | xtwork | v2 |
|---|---|---|
| 界面 | mygo 原生界面（3E 系列切片） | T3 的 React 界面 |
| 运行时 | Pi sidecar | Dim（Pi 留作替补） |
| 对话与持久化 | 自建 session log、timeline | T3 的编排与持久化 |
| 插件宿主位置 | mygo 宿主进程内 | T3 服务端的子进程 |
| 插件 | moejs，使用过未冻结的 1.3 插件角色 | moejs，v2 自己锁定插件契约（见 [05](05-插件系统.md)） |

迁移细节见 [12](12-从xtwork迁移.md)。
