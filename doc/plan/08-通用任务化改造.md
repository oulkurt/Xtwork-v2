# 08 通用任务化改造

> 回答：把一个面向写代码的产品改成面向通用任务，具体改哪里、怎么改。
> 【已定】产品以通用任务为主。Pull requests、Issues 等代码功能不在首页出现，只在设置里体现；具体清单待定。（2026-11-19）
> 相关：[02 上游与改造层](02-上游与改造层.md) · [05 插件系统](05-插件系统.md) · [11 风险与待定](11-风险与待定.md)

## 1. 原则

- 保留上游功能实现，在改造层调整可见入口。
- 用统一读取点控制开发者功能。
- 开发者打开开关后，在设置里访问 Pull requests 和 Issues，保留上游操作行为。

## 2. 开发者功能开关【建议】

- 位置：设置 → 开发者功能 →“显示开发者功能”。默认关。
- 存储：服务端设置（`packages/contracts/src/settings.ts`）新增一个布尔字段，例如 `developerFeatures.enabled`。放在服务端设置而不是客户端设置，多个窗口和远程客户端看到的结果一致。
- 读取：界面新增 `useDeveloperFeatures()`。用它控制设置里的开发者入口和其它候选入口。首页的 PR 和 Issues 导航迁入设置。
- 服务端不改：功能仍然存在，只是没有入口。
- 不靠这个开关处理的功能：遥测、T3 Connect 这类“产品里不应运行”的功能，由 [09](09-品牌与发布.md) 直接关闭。

现状：侧栏底部的 Pull requests 和 Issues 只看“当前环境是否支持”（`apps/web/src/components/sidebar/SidebarChrome.tsx:289` 的 `pullRequestsSupported`、`:296` 的 `issuesSupported`；数据来自 `apps/web/src/state/environments.ts:112-118` 的 `usePullRequestsSupported()`、`useIssuesSupported()`）。没有任何用户设置能隐藏它们，所以必须打补丁（P-04）。侧栏底部现在的四项是：Settings、Pull requests、Issues、Usage。

## 3. 受开关控制的入口（候选清单）【待定 Q-02】

| 入口 | 上游位置 | 建议 |
|---|---|---|
| 侧栏 Pull requests | `SidebarChrome.tsx:289` | 移到设置 → 开发者功能 |
| 侧栏 Issues | `SidebarChrome.tsx:296` | 移到设置 → 开发者功能 |
| Pull requests 设置分区 | `apps/web/src/components/settings/SettingsPanels.tsx:1743` | 在开发者功能启用后可用 |
| 代码托管账号（GitHub、GitLab、Azure DevOps、Bitbucket、Forgejo 等） | `packages/source-control-*` 的设置与登录 | 隐藏 |

| 分支、工作树（worktree） | 对话头部、设置 | 隐藏 |
| 改动对比（diff）、检查点（checkpoint） | 对话侧栏 | 隐藏【待定：普通用户也许想看“这次改了哪些文件”】 |
| 终端 | 面板 | 隐藏 |
| 用编辑器打开 | 对话头部 | 隐藏 |
| 克隆仓库 | 新建项目 | 隐藏 |

开工时先做一次全量盘点，把命令面板、快捷键、右键菜单、空状态提示里的代码相关入口也找出来，补全这张表。

## 4. 新对话默认免项目【建议】

上游已有“无项目”模式：
- RPC：`projects.ensureScratch`（`packages/contracts/src/rpc.ts:451`），返回 `ProjectEnsureScratchResult { projectId }`（`contracts/src/project.ts`）。
- 服务端配置：`scratchWorkspaceRoot`（`contracts/src/server.ts:734`）；环境字段 `threadProjectFromScratch`（`contracts/src/environment.ts:141`）。
- 目录：`<baseDir>/scratch`（`apps/server/src/project/ManagedProjectFolders.ts:70`）。baseDir 位于 git 仓库内时，这个模式不可用。

改造：
- 新对话默认进入免项目模式。
- “在文件夹里工作”作为可选动作，选了文件夹才创建普通项目。
- 【待验证】免项目对话共用一个 scratch 目录。两个对话同时写同名文件会冲突；必要时按对话建子目录。

## 5. 运行时与模型选择

- 默认只启用内置运行时；只有一个运行时时隐藏选择器（P-06）。
- M1 使用已验收的默认模型。ACP 实测支持切换后再显示“标准”“深度”等选项，见 [13](13-模型网关.md)。

## 6. 术语【建议】

上游用 General Translation（gt）做国际化：`apps/web/src/i18n/`，API 为 `gt()`、`<T>`、`msg`；已有 de、en、es、fr、ja、ko、pt-BR、ru、sv、zh 十种语言，支持的语言由 `gt.config.json` 决定。

改造层放一份 zh.json 覆盖，只改术语，不改文案结构。初步用词：

| 上游概念 | 产品用词 |
|---|---|
| thread | 对话 |
| project | 文件夹 |
| provider（运行时） | 不出现 |
| worktree | 不出现（开发者功能） |
| scheduled task | 定时任务 |
| skill | 技能 |
| turn | 尽量不出现 |

开工时先导出上游 zh.json 的现有译法，对照这张表逐条确认。英文界面同样处理（en.json 覆盖）。

## 7. 首页与空状态

- 输入框占主位。
- 空状态给出通用任务示例：整理会议纪要、写一封邮件、规划这周日程、总结一篇笔记。
- 左下角保留：设置、用量。
- 插件入口（待办、日程、笔记）进侧栏或面板区，见 [05 §7](05-插件系统.md#7-界面槽位建议)。

## 8. 验收

- 开关关闭：在首页、侧栏、命令面板、输入框、设置页都找不到第 3 节中标为“隐藏”的入口。
- 开关打开后，从设置访问 Pull requests 和 Issues。首页继续显示通用任务入口。
- 新用户第一次打开，不选文件夹就能开始对话并得到回复。
- 日常界面和助手自我介绍使用自有品牌。开源许可页可查第三方归属（见 [09](09-品牌与发布.md)）。
