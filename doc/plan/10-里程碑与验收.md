# 10 里程碑与验收

各阶段的实现进度与已跑过的测试见 [当前进度](../README.md#当前进度)。

【建议】先用一轮本机对话证明桌面壳和助手能配合，再做首页和插件。每个里程碑以可复现的用户操作验收。

## M0 · 跑通桌面、T3 和 Pi

1. 记录 T3、mygo、Node、Pi 的锁定版本，按 [04](04-mygo外壳.md) 启动。
2. 在 macOS arm64 上启动 T3 Node 服务端，mygo WebView 加载本机界面。先验证浏览器模式，再验证生产构建的同源页面、preload 和最小桌面桥接。
3. 用随包 Pi 启动原生 RPC。验证模型发现、首字流式输出、待办 MCP、取消、权限拒绝、自我介绍以及重启后原线程续聊，记录命令、版本和结果。
4. 关闭窗口、重新打开、彻底退出。核对何时保留后台进程。确认显式退出后，这次启动的服务端、Pi RPC 进程、插件宿主和 worker 都已退出。

**通过条件**　新数据目录能首启、收到流式回复、创建待办并在重启后读回。检查一份旧 Alpha 数据的默认设置迁移、对话和待办。Windows 启动信息和子进程管理的验证可以独立进行。

## M1 · 通用任务桌面版

- 完成首启默认配置、品牌和基础桌面桥接。模型只用一个已验证的默认别名，等切换链路通过后再显示第二个选项。
- 新对话默认使用免项目工作区。验收两个会话是否共享目录，以及选文件夹时的权限和恢复行为。
- 设置中有开发者功能。Pull requests、Issues 只从这一区域进入。验证设置关闭、开启和重启后的入口状态。
- 首轮安装包能在干净 macOS 机器启动。首启和聊天只连接预期的产品服务及模型通道。

**通过条件**　普通用户安装后能开始第一个任务。用临时模型凭据做内部预览即可，面向用户的开箱路径等 Q-03 确定后验收。

## M2 · 插件通路

- Go 插件宿主带一个测试 worker，接通 JSONL 加载、工具调用、授权和停止。
- 插件桥把一个工具接进 Pi 的会话 MCP，并返回插件写入结果。在界面只展示实际已执行的操作。
- 接通一个 @ 上下文条目和一个沙箱面板。核对手工选择、移除、权限拒绝、退出后恢复。
- 核对 MCP 工具是否需要特别暴露、权限是否重复弹窗。用一条测试流程打通确认、拒绝和撤销。
- 冻结这一阶段实际用到的 v2 插件契约和最小夹具。
- 第一阶段补齐 v2 清单强判别、功能与外观双轨注册、结构化诊断，以及基于 `AppRouteModal` 的 `PluginModalHost`。

**通过条件**　同一测试插件能经对话和面板访问同一份状态。重复发送或重试只写一次，禁用插件后新工具调用无法执行。

## M3 · 三个内置插件

- 待办先完成，日程接上时区和通知，Obsidian 接上目录授权与引用。三者按 [06](06-内置插件-待办日程笔记.md) 验收。
- 把「记录行动」「安排会议」「引用笔记」做成三条完整操作，从首启到结果可见。
- 评估 Windows 与 macOS 的系统通知和选择目录。目标平台的真实打包环境跑一遍。

**通过条件**　聊天创建的待办和日程能在面板看到，撤销可用。笔记可随对话发送并指明来源，未授权目录不可读。

## M4 · 首个远程连接试点

- 【建议】先选一个有测试租户的平台完成闭环。飞书作为当前候选，四个平台的范围由 Q-04 决定。
- 跑通绑定、接到一条私聊消息、创建或续接任务、回最终结果。需要在 IM 审批的功能单独验证并经范围确认后再开放。
- 验收断线重连、重复回调、设备离线、解绑和后台退出。其余平台各自对照 [07](07-远程连接插件.md) 补齐支持证据。

**通过条件**　绑定用户发来的同一条消息最多执行一次，试点功能可以随时从桌面断开。桌面首发可以独立发布，远程连接在通过平台验收后按平台启用。

## M5 · 发布候选

按 [09](09-品牌与发布.md) 完成签名、许可归属、安装升级和出站检查。至少保留一份安装包及验收环境、运行命令、通过项和仍限制的功能。若引入旧数据导入，先用备份副本走一次 [12](12-从xtwork迁移.md) 的验收。

## 依赖关系

`M0 → M1 → M3` 与 `M0 → M2 → M3`。M2 可以在 M1 打磨界面时并行。M4 依赖 M2，经批准的远程功能不妨碍 M3 成为桌面预览版。M5 按本次发布范围核对已完成的里程碑。
