# 06 内置插件：待办、日程、Obsidian

【已定】三项功能与聊天共用同一个 agent 上下文。对话可以创建和查询条目，面板可以独立管理条目。插件返回真实的写入结果，界面据此显示新条目、时间和可用的后续操作。

相关：[05 插件系统](05-插件系统.md) · [10 里程碑与验收](10-里程碑与验收.md)

## 1. 对话怎么决定用哪个插件

| 用户在聊天里说 | 处理方式 | 界面结果 |
|---|---|---|
| 周五前把季度报告发给王总 | 写入待办，周五是截止日 | 「已加入待办」及截止日期，支持打开和撤销 |
| 明天下午三点到四点和小周开评审会 | 写入日程，使用产品当前时区换算日期 | 「已加入日程」及起止时间，支持打开和撤销 |
| 明晚八点提醒我交报告 | 写入带提醒的待办 | 同一条待办显示提醒时间 |
| 周五可能有个会议 | 等用户确定日期或明确要记，再写入 | 澄清问题，或继续讨论 |
| 帮我总结《季度复盘》那篇笔记 | 在已授权的 vault 搜索，读取匹配的笔记 | 回复附来源，可打开原文 |
| 把刚才三条结论追加到《季度复盘》 | 读取现版，展示写入确认，批准后写入 | 成功显示文件名，发生冲突时请用户看新版 |

【建议】有明确行动意图的单条待办、日程直接记，成功后可撤销。假设、引用、别人说过的行动、模糊时间和批量删除由 agent 先确认必要信息。一条消息有两个独立意图时可分别调用，例如「记下周一评审，也提醒我周日准备提纲」。界面准确显示每次写入的结果。

系统提示告诉 agent 如何挑工具。真正的写入发生在工具调用里。回合结束事件只负责刷新或展示结果，避免 agent 和消息观察器各记一次。宿主为同一次对话操作分配稳定操作键，重试时返回原结果。撤销只作用于当次创建的记录。记录已经编辑或完成时，要求用户在面板处理。

## 2. 待办

- v1 面板支持新增、编辑、完成、删除和未完成筛选。记录有 `id`、标题、状态、可选截止日期、提醒时间、来源对话及更新时间。用户可以手工新增，同一份记录也能用聊天查询或修改。
- 无时刻的截止日作为本地日期保存。提醒时间以带偏移的时间戳保存。只有用户指定提醒，才调度系统通知。
- 聊天工具建议沿用 `todo__create`、`todo__update`、`todo__complete`、`todo__delete`、`todo__list`。修改前用条目 id 定位。多个同名条目时先展示候选。
- @ 选择器可把一条待办附到消息。上下文类型为 `todo-item`，包含条目 id、标题、状态和截止日期。上下文是发送时的快照，执行前仍可查最新状态。

## 3. 日程

- v1 支持本地日程和系统提醒。记录包含标题、起止时间、时区、可选地点和提醒。全天记录以日期保存，定时记录保存带偏移的时间戳和 IANA 时区。重复日程属于独立验收项。
- 建议宿主工具 `app__current_time` 返回当前时间及 IANA 时区。处理「明天」「下周三」先取这个值，查看旧消息中的相对日期时沿用原消息语境。缺结束时间时建议按 30 分钟展示，并在确认条里写清楚。
- 聊天工具建议沿用 `calendar__create`、`calendar__update`、`calendar__delete`、`calendar__list`。创建前验证结束晚于开始，修改或删除时按日程 id 定位。@ 选择器使用 `calendar-event`。
- 通知调度由宿主负责。关闭窗口后如果宿主仍在运行，可继续提醒。退出应用或休眠后的提醒规则在发布验收中单独跑。飞书、系统日历等外部同步作为单独能力评估。

## 4. Obsidian 笔记

【建议】以用户选中的本地 vault 为范围。选好之前，笔记面板提供「连接笔记库」，当前对话仍可继续。打开 Obsidian 本体属于便捷操作，本地 Markdown 读取不依赖它处于打开状态。

1. 在聊天框输入 @，选「笔记」和目标条目。发送前可移除引用；消息随附 `obsidian-note`，字段包括 vault 内相对路径、标题、更新时间、内容片段和是否截断。
2. 问题明确指向笔记时，agent 可在当前对话调用 `obsidian__search`，再按匹配路径调用 `obsidian__read`。对泛化问题只可建议候选，用户接受后再附正文。空结果提示找不到并允许改关键词或换 vault。
3. 向模型发送实际使用的片段，并标记来源。默认单条最多 8,000 字符，插件上下文合计最多 24,000 字符。笔记正文作为资料，不改变当前对话的用户指令和授权。
4. 首发验收读与引用。启用写入时，`obsidian__write` 必须由用户确认具体路径和改动。更新带读取时的 `expectedSha256`，冲突时保留磁盘上的新版并重新展示改动。

安装包可带插件，选取 vault 后才授予目录能力。宿主限制在选中目录内，拒绝出目录的链接。使用云模型时，附给对话的笔记片段会随模型请求发送，界面在连接或发送入口说明这一点。

## 5. 验收

- 同一条发送重试只生成一条待办；撤销后面板、存储和提醒一致。
- 在固定的当前时间和时区下，「明天下午三点」保存为正确日期；退出重开后日程仍可查。
- 把笔记附到输入框再移除，模型请求里没有该笔记正文。发送另一篇时，回复能指出正确来源。
- 对话里直接查询「我这周有什么会」「还有哪些待办」，结果与面板一致。
- 未授权 vault 时读不到文件。授权后可读库内笔记。写入提议被拒绝或出现版本冲突时，原文件保持原样。
