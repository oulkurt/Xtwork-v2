# 10 里程碑与验收

各阶段的实现进度与已跑过的测试见 [当前进度](../README.md#当前进度)。

【建议】先用一轮本机对话证明桌面壳和助手能配合，再做首页和插件。每个里程碑以可复现的用户操作验收。

## M0 · 跑通桌面、T3 和 Pi

1. 记录 T3、mygo、Node、Pi 的锁定版本，按 [04](04-mygo外壳.md) 启动。
2. 在 macOS arm64 上启动 T3 Node 服务端，mygo WebView 加载本机界面。先验证浏览器模式，再验证生产构建的同源页面、preload 和最小桌面桥接。
3. 用随包 Pi 启动原生 RPC。验证模型发现、首字流式输出、待办 MCP、取消、权限拒绝、自我介绍以及重启后原线程续聊，记录命令、版本和结果。
4. 关闭窗口、重新打开、彻底退出。核对何时保留后台进程。确认显式退出后，这次启动的服务端、Pi RPC 进程、插件宿主和 worker 都已退出。

**通过条件**　新数据目录能首启、收到流式回复、创建待办并在重启后读回。检查一份旧 Alpha 数据的默认设置迁移、对话和待办。Windows 启动信息和子进程管理的验证可以独立进行。

## M2 · 插件通路

- Go 插件宿主带一个测试 worker，接通 JSONL 加载、工具调用、授权和停止。
- 插件桥把一个工具接进 Pi 的会话 MCP，并返回插件写入结果。在界面只展示实际已执行的操作。
- 接通一个 @ 上下文条目和一个沙箱面板。核对手工选择、移除、权限拒绝、退出后恢复。
- 核对 MCP 工具是否需要特别暴露、权限是否重复弹窗。用一条测试流程打通确认、拒绝和撤销。
- 冻结这一阶段实际用到的 v2 插件契约和最小夹具。
- 第一阶段已合入 `main`（[PR #11](https://github.com/oulkurt/Xtwork-v2/pull/11)–[PR #13](https://github.com/oulkurt/Xtwork-v2/pull/13)）：补齐 v2 清单强判别、功能与外观双轨注册、结构化诊断，以及基于 `AppRouteModal` 的 `PluginModalHost`；待办操作回执、撤销与 `@` 上下文已于 [PR #10](https://github.com/oulkurt/Xtwork-v2/pull/10) 合入。

**通过条件**　同一测试插件能经对话和面板访问同一份状态。重复发送或重试只写一次，禁用插件后新工具调用无法执行。

## M4 · IM 远程连接（飞书、微信 iLink、企业微信）

- 【已定】按 [ADR-011](../decisions/011-mingle-im-bridge.md) 交付 T3 侧独立 Node `im-bridge`（复用 Mingle MIT 渠道层与状态机），首发范围已定为飞书、个人微信（iLink）和企业微信（收口 Q-04）；Leader 主管控制面演进见 [ADR-013](../decisions/013-leader-supervisory-threads.md)。
- **已合入 `main`（PR #15–#18、#21、#25、#31、#34）**：`im-bridge` 守护进程、飞书/企微/个人微信渠道适配器、配对认领与门禁、T3 双层安全闸门（Pi 目录外读写拦截 + 私有/群待办隔离）、应用打包、独立侧栏「远程连接」镭射卡 UI，以及 [ADR-013](../decisions/013-leader-supervisory-threads.md) 领航者（Leader）Slice 1（默认 Leader、按 run 持久化 fail-closed 策略、侧栏顶部固定主管槽位、Needs You 聚合与暂停/恢复重投）与 Slice 2（多领航者创建与归档、IM 渠道原子换绑、按受众分级的 IM 委派/进展汇报审批策略、「领航者 / 对话」侧栏分栏与动态 Bot 头像）。
- **待真机验收与后续阶段**：飞书、企业微信、个人微信真机私聊/群 `@`、断线重连、休眠醒来重连、崩溃补投幂等、解绑、无全局 Node 打包启动和退出零残留；个人微信（iLink）另须完成实名/PIN、主动发送限制与第三方分发合规验收；IM 内卡片审批（Q-09）与 Leader Stage 2/3（Q-13）按排期验收。

**通过条件**　同一外部消息（含平台重推与落盘后仅针对已通过门禁触发消息的崩溃补投）最多创建一个 T3 回合，执行中途崩溃的回合不自动盲重跑；群聊与桌面私有历史按受众严格隔离；所有 IM 来源回合及 `group` 受众回合（含桌面显式回复到群）的目录外原生读写、所有 `bash` / 进程执行（无论工作目录）、以及群受众对 Owner 私有数据的访问均需 Owner 单次批准；个人微信（iLink）通过真机与分发合规验收后再正式对外开放；试点功能可随时从桌面暂停或解绑。桌面首发可独立发布，各 IM 渠道通过真机验收后逐个启用。

`M0 → M1 → M3` 与 `M0 → M2 → M3`。M2 可以在 M1 打磨界面时并行。M4 依赖 M2，经批准的远程功能不妨碍 M3 成为桌面预览版。M5 按本次发布范围核对已完成的里程碑。
