# 08 通用任务化改造

> 回答：把一个面向写代码的产品改成面向通用任务，具体改哪里、怎么改。
> 【已定】产品以通用任务为主。Pull requests、Issues 等代码功能不在首页出现，只在设置里体现；具体清单待定。（2026-11-19）
> 相关：[02 上游与改造层](02-上游与改造层.md) · [05 插件系统](05-插件系统.md) · [11 风险与待定](11-风险与待定.md)

## 1. 原则

- 保留上游功能实现，在改造层调整可见入口。
- 用统一读取点控制开发者功能。
- 开发者打开开关后，在设置里访问 Pull requests 和 Issues，保留上游操作行为。

## 2. 开发者功能开关【建议】

- 位置：设置 → 开发者功能 →“显示开发者功能”。默认关。
- 存储：服务端设置（`packages/contracts/src/settings.ts`）新增一个布尔字段，例如 `developerFeatures.enabled`。放在服务端设置而不是客户端设置，多个窗口和远程客户端看到的结果一致。
- 读取：界面新增 `useDeveloperFeatures()`。用它控制设置里的开发者入口和其它候选入口。首页的 PR 和 Issues 导航迁入设置。
- 服务端不改：功能仍然存在，只是没有入口。
- 不靠这个开关处理的功能：遥测、T3 Connect 这类“产品里不应运行”的功能，由 [09](09-品牌与发布.md) 直接关闭。

实建状态（`main@62e84cb`）：上游侧栏底部的 Pull requests 和 Issues 原本只看环境支持度（`SidebarChrome.tsx:289`、`:296`）。[PR #19](https://github.com/oulkurt/Xtwork-v2/pull/19)（`037-developer-features.patch` + `useDeveloperFeatures.ts` + `desktopFeatureVisibility.ts`）已将 PR / Issues / Git / Worktree / 终端 / 外部编辑器等收口至「设置 → 通用 → 开发者功能」，侧栏底部默认保留待办、设置与用量；[PR #26](https://github.com/oulkurt/Xtwork-v2/pull/26)、[PR #28](https://github.com/oulkurt/Xtwork-v2/pull/28) 与 [PR #29](https://github.com/oulkurt/Xtwork-v2/pull/29) 已在普通模式开放 `/settings/channels` 模型渠道、`/settings/providers` 六大外部编码 Agent 卡片与 Coding Agent 委派设置。

## 4. 新对话默认免项目【建议】

上游已有“无项目”模式：
- RPC：`projects.ensureScratch`（`packages/contracts/src/rpc.ts:451`），返回 `ProjectEnsureScratchResult { projectId }`（`contracts/src/project.ts`）。
- 服务端配置：`scratchWorkspaceRoot`（`contracts/src/server.ts:734`）；环境字段 `threadProjectFromScratch`（`contracts/src/environment.ts:141`）。
- 目录：`<baseDir>/scratch`（`apps/server/src/project/ManagedProjectFolders.ts:70`）。baseDir 位于 git 仓库内时，这个模式不可用。

改造：
- 新对话默认进入免项目模式。
- “在文件夹里工作”作为可选动作，选了文件夹才创建普通项目。
- 【待验证】免项目对话共用一个 scratch 目录。两个对话同时写同名文件会冲突；必要时按对话建子目录。

## 5. 运行时与模型选择

- **当前实建（`main@62e84cb`）**：默认首选内置助手「**小瞳**」（`xtworkPi`，已于 [PR #24](https://github.com/oulkurt/Xtwork-v2/pull/24)、[PR #28](https://github.com/oulkurt/Xtwork-v2/pull/28) 落地更名、多协议 Proxy-Only 网关、企业微信公司渠道与 19 类供应商 `/settings/channels` UI）。[PR #26](https://github.com/oulkurt/Xtwork-v2/pull/26) 与 [PR #29](https://github.com/oulkurt/Xtwork-v2/pull/29) 已在普通模式完整落地 `/settings/providers` 与 **Claude Code、Codex、Kimi Code、Qoder、Codebuddy Code、DeepSeek Harness** 6 张卡片、服务端统一 Install Consent Gate、Provider Provisioner 与「Coding Agent」确定性委派设置及阻断操作卡（其余非核心上游驱动仍保留在开发者功能中）。
- **待真机实跑验收**：真实线上企业微信/供应商账号回归，以及无全局 Node/npm/Homebrew 干净机器上的 6 款外部 Agent 真实安装与端到端委派验收。

## 6. 术语与默认语言【已定】

- 桌面版默认界面语言为**简体中文（`zh`）**，当前仅提供**简体中文（`zh`）与 English（`en`）**两种选项（移除「跟随系统」及另外 8 种语言，已于 [PR #20](https://github.com/oulkurt/Xtwork-v2/pull/20) 落地）。
- 上游用 General Translation（gt）做国际化：`apps/web/src/i18n/`，API 为 `gt()`、`<T>`、`msg`。改造层维护 `zh.json` 术语覆盖：

| 上游概念 | 产品用词 |
|---|---|
| thread | 对话 |
| project | 文件夹 |
| built-in Pi (`xtworkPi`) | 小瞳 |
| model channel（小瞳内模型来源） | 渠道 / 模型供应商（团队渠道 / 个人渠道） |
| external coding provider | 编码 Agent / Coding Agent |
| worktree | 不出现（开发者功能） |
| scheduled task | 定时任务 |
| skill | 技能 |
| turn | 尽量不出现 |

## 7. 首页与空状态

- 输入框占主位。
- 空状态给出通用任务示例：整理会议纪要、写一封邮件、规划这周日程、总结一篇笔记。
- 左下角保留：设置、用量。
- 插件入口（待办、日程、笔记）进侧栏或面板区，见 [05 §7](05-插件系统.md#7-界面槽位建议)。

## 8. 验收

- 开关关闭：在首页、侧栏、命令面板、输入框、设置页都找不到第 3 节中标为“隐藏”的入口。
- 开关打开后，从设置访问 Pull requests 和 Issues。首页继续显示通用任务入口。
- 新用户第一次打开，不选文件夹就能开始对话并得到回复。
- 日常界面和助手自我介绍使用自有品牌。开源许可页可查第三方归属（见 [09](09-品牌与发布.md)）。
